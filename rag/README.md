# rag/

Document Intelligence + Retrieval-Augmented Generation — [ARCHITECTURE.md §14](../ARCHITECTURE.md#14-layer-11--rag--document-intelligence), built in **[ROADMAP.md Sprint 12](../ROADMAP.md)**.

```
rag/
├── ingestion/       # loads the 4 synthetic policy docs (data/documents/) into the parsing pipeline
├── parsing/         # wraps Snowflake AI_PARSE_DOCUMENT / AI_EXTRACT — layout-aware chunking
├── embeddings/       # wraps AI_EMBED, writes vectors + chunk metadata to the Cortex Search index
├── retrieval/          # queries Cortex Search, returns top-k chunks joined with customer/order state
└── evaluation/           # golden Q&A set + retrieval precision@k measurement
```

## What gets ingested

`refund_policy.md, delivery_policy.md, loyalty_policy.md, privacy_policy.md` — four synthetic
corporate policy documents generated by
[`data/synthetic/generators/documents.py`](../data/synthetic/generators/documents.py). That
generator writes Markdown source (always) and attempts a PDF render via `data/documents/render.py`
if `reportlab` is installed (`pyproject.toml`'s `docs-pdf` extra) — PDF is a nice-to-have for
demoing `AI_PARSE_DOCUMENT` against a "real" document format, not a hard requirement, since the
pipeline can ingest the Markdown directly when no renderer is available.

## Pipeline

1. **`ingestion/`** picks up the documents (Markdown or PDF) from `data/documents/`.
2. **`parsing/`** calls `AI_PARSE_DOCUMENT` (or `AI_EXTRACT` for structured fields, e.g. the
   loyalty tier table) to turn each document into layout-aware chunks — this is Snowflake Cortex
   doing the parsing, not a local PDF library, per [ARCHITECTURE.md §12](../ARCHITECTURE.md#12-layer-9--snowflake-enterprise-dwh--cortex).
3. **`embeddings/`** calls `AI_EMBED` on each chunk and indexes the result in **Cortex Search**.
4. **`retrieval/`** queries the Cortex Search index at question time and joins the retrieved
   policy text with live customer/order data (e.g. *"Is this customer eligible for a refund?"*
   needs both the refund policy text **and** that customer's actual order/delivery status) — this
   join is what makes it retrieval-augmented generation and not just document search.
5. **`evaluation/`** holds a hand-written golden Q&A set (question → expected chunk(s)/answer) and
   scores retrieval precision@3 against it.

## What "done" looks like (Sprint 12 acceptance criteria)

Retrieval precision@3 **≥ 0.8** on the golden set — see [ROADMAP.md Sprint 12](../ROADMAP.md).
Results get recorded in [`../benchmarks/cortex.md`](../benchmarks/cortex.md) as the RAG/retrieval
rows alongside Cortex Analyst SQL/answer accuracy, since both are evaluated against golden
question sets with the same "measured, not assumed" discipline as `snowflake/evaluations/`.
