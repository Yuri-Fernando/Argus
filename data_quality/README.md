# data_quality/

The GX Core (Great Expectations 1.0+) data quality framework — ARCHITECTURE.md §7, built in **Sprint 3**.

```
data_quality/
├── rules/           # human-readable rule catalog (completeness/validity/uniqueness/referential/freshness/schema)
├── expectations/    # GX Expectation Suites, one per Silver table
├── validators/       # Checkpoint definitions wiring suites to Databricks jobs (fail/quarantine on breach)
├── monitoring/         # native Databricks Data Quality Monitoring config (statistical drift, complementary to GX's
│                        # declarative rules — see ARCHITECTURE.md §7)
└── reports/             # generated GX Data Docs (HTML) + quality_report.json — gitignored, regenerated by `make dq`
```

## Run it

```bash
make dq   # = python data_quality/run_checkpoint.py --suite customer_suite
```

## What "done" looks like (Sprint 3 acceptance criteria)

Intentionally corrupting a field via `data/synthetic/config.yaml`'s `dirty_rates` causes the relevant Checkpoint to fail and the affected rows to land in `data/quarantine/` — verified by `tests/data/test_dq_quarantine.py`.
