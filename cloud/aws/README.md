# cloud/aws/

This is a **documented portability target only** — per [ADR-001](../../docs/decisions/ADR-001-cloud-strategy.md), AWS is **not implemented** for this platform; the full service-by-service mapping (with migration-relevant behavioral differences) lives in [`../architecture-comparison.md`](../architecture-comparison.md). If a specific target role or opportunity requires a real AWS deployment, this is where that Terraform AWS module set would go — `modules/aws/` mirroring the structure of `terraform/modules/azure/` for the Azure-specific pieces (storage, ingestion, identity, monitoring, AI serving), while the Databricks and Snowflake modules under `terraform/modules/{databricks,snowflake}/` would be **reused unchanged**, since both are cloud-agnostic by nature and already work identically regardless of which cloud hosts them.
